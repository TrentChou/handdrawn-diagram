# Motion · 动态讲解（slides / 视频）

同一套手绘图，除了导出一张张 PNG，还可以做成**动态讲解**：读者从总览一路走进细节，再回到总览。两张图都出现的概念不会消失再出现，而是**移动、变形过去**（类似 Keynote 的「神奇移动」）。

产物有两种：

- `deck.html`：单个离线文件，在浏览器里全屏放映，键盘翻页。
- `deck.mp4`：同一份 deck 逐帧录成的视频，1080p，也可以出 4K。

这里讲的内容不限于软件架构。业务流程、物理系统、自然过程，只要能画成「总览 + 若干细节图」，都适用。

两个可以直接运行、对照阅读的例子：

- `examples/water-supply/`：**入门**。城市供水，2 张图、5 页，本文的代码片段都摘自这里。
- `examples/vertical-search/`：**进阶**。垂直搜索引擎，3 张图、11 页，多了一拆三、在框外显式写 `parent`、同一概念在三张图之间流转。

## 什么时候用

| 读者的处境 | 输出 |
|---|---|
| 文章配图、文档插图、打印；一张图就能看懂 | 静态 PNG（默认，按 SKILL.md 的流程） |
| 有人在屏幕前被领着看：汇报、讲课、录屏、发视频 | 动态 deck |
| 一张图太密，要拆成「总览 + 放大图」，并且希望读者看清放大图是从哪里展开的 | 动态 deck |
| 用户明确要 slides、动画、视频、神奇移动 | 动态 deck |

动态 deck 不需要另一套画法。每张图仍然是按 SKILL.md 画出来、能单独导出 PNG 的静态图，只是多声明了每个概念的**身份**（第 1.3 节讲为什么，第 4 节讲怎么写）。

---

## 1. 原理

### 1.1 一套图就是一本地图集：内容多与内容具体

城市地图上什么都有，但商场只是一个色块。商场的室内图只画这一个商场，但每家店、每部扶梯都画得很清楚。两者是**同一个地方、两种比例尺**：

- **总览图**：内容多，每样东西都画得粗。
- **细节图**：内容少，只展开总览上的某一个概念，或几个相邻的概念，每样东西都画得具体。

规则：

- 每张细节图都能指回总览上的一个位置，读者要知道它是从哪里展开的。
- 细节图要保留被展开概念的**邻居**（左边从哪里来，右边到哪里去），画在画面边缘，作为读者认路的锚。
- 粒度一次只跨一级。总览直接跳到第三级细节，读者会迷路。

「展开」不只是放大一种。按读者想知道什么来选：

| 细节类型 | 展开的是 | 例子 |
|---|---|---|
| 放大 | 一个概念的内部构成 | 城市供水总览里的「水厂」→ 混凝、沉淀、过滤、消毒 |
| 路径切片 | 一条路线依次经过的环节 | 一个包裹从揽收到签收经过的站点 |
| 时间轴 | 一个概念随时间的阶段 | 水库一年里的蓄水、供水、汛期泄洪 |
| 多实例对比 | 同一概念的几个实例并排 | 三家门店各自的出餐流程 |
| 分层 | 同一空间的不同层 | 城市的地面道路、地铁、地下管网 |

### 1.2 对象恒常性：同一个概念不消失，变形过去

一个概念如果在前后两张图上都出现，转场时读者必须能把它看成**同一个东西**。它可以移动、缩放，形状可以变（方框变成分组框），文字可以扩写或缩写（「水厂」变成「水厂 · 日处理 50 万吨」），但不能先淡出再从别处淡入。读者一旦看到它消失，就要重新找一遍，刚建立的地图也就断了。

只在一侧出现的东西才淡入淡出。

播放器支持的对应方式：

| 前一张 | 后一张 | 转场里发生的事 |
|---|---|---|
| 方框 | 方框 | 移动、缩放到新位置，文字跟着走 |
| 方框 | 分组框 | 方框撑开成虚线分组框，名字飞到分组框的标题位置，成员从框里长出来 |
| 一行文字 | 方框 | 方框围绕这行字长出来；反过来就是缩回成一行字 |
| 1 个 | 多个（拆分） | 子概念从父概念的框里长出来，各自飞向落点 |
| 多个 | 1 个（合并） | 拆分的反向：子概念飞回父概念、并入它 |
| 箭头 | 箭头 | 两端始终挂在所连的概念上；线只伸缩，不变粗，箭头头部只转向、不变形 |

研究依据：Heer & Robertson 的 [Animated Transitions in Statistical Data Graphics](https://idl.cs.washington.edu/files/2007-AnimatedTransitions-InfoVis.pdf)（2007）用实验说明，保持对象恒常性、把复杂转场分阶段的动画，比直接切换更容易被读懂。Keynote 的[神奇移动](https://support.apple.com/zh-tw/guide/keynote/tanff5ae749e/mac)是同一个思路：两张幻灯片都有的物件参与过场，只在一张上有的淡入或淡出。

### 1.3 为动画而画：显式声明身份

播放器怎么知道前后两张图上的哪两个东西是「同一个概念」？**靠你声明**。每个在两张以上图里出现的概念，给它一个稳定的 id，所有图里写同一个 id：

```js
// examples/water-supply/01_overview.html：总览里的水厂是一个加粗的大方框
node(450, 245, 320, 170, C.agent, '水厂', '净化 · 消毒',
     { box: { strokeWidth: 3 }, size: 30, subSize: 17, id: 'plant' });

// examples/water-supply/02_plant.html：同一个概念变成了分组框，标题也换了说法
frame(300, 240, 1230, 220, C.agent, '水厂 · 日处理 50 万吨', 230, { id: 'plant' });
node(340, 295, 190, 120, C.subagent, '混凝', '加药 · 凝成絮体', { id: 'coagulation' });   // 画在框里：属于 plant
// （示例里四道工序用一个循环画出，这里展开了第一道）
```

- id 用英文短横线写法（`water-source`、`plant`、`pipe-network`），表示的是概念，不是某张图上的某个形状。
- 子概念要知道自己属于谁。画在父概念的方框或分组框**里面**的（方框、分组框、自己带 id 的文字都算），会自动推断出 parent；画在外面的，显式写，比如画在水厂框外的污泥池：`{ id: 'sludge-tank', parent: 'plant' }`。
- 有 parent 的子概念，在只有父概念的那张图上，会从父概念里拆出来、或合并回去。
- parent 只管「属于谁」，和颜色无关。子概念可以用和父概念不同的颜色，按绑定表来。
- 没写 id 的东西，退回到按文字配对：两侧文字完全相同（开头的步骤号可以不同）才算同一个。所以措辞一改就配不上了。凡是跨图出现的概念，都写上 id。

### 1.4 布局连续：保住读者心里的地图

读者看总览时，已经在心里记下了「水源在左、水厂在中、用户在右」。细节图要顺着这张心里的地图来画：

- 细节图里，展开的概念放在中间，它的邻居仍然放在**原来的方位**：总览里水源在水厂左边，细节图里水源也在左边缘。
- 主流向在整套图里保持不变，例如一律从左到右。
- 同一个概念，颜色在所有图里都不变（由绑定表锁定），形状可以变。

### 1.5 镜头与叙事

每一页 = 一张图 + 一个镜头。镜头可以看整张图，也可以推近到某个区域，其余部分压暗。

- **同一张图内，用镜头推近**；**换图才变形**。不要为了讲一个局部专门再画一张图。
- **先推镜头，再换图**：要展开某个概念时，先在总览上把镜头推到它身上，下一页才变形成细节图。读者因此知道「我们走进了哪里」。
- **每个镜头只讲一个结论**。一页想讲两件事，就拆成两个镜头。在 deck.json 里给每页写一句 `note`（这一页要讲的那句话），写不出一句话，说明这一页还没想清楚。
- **回到总览**用来收束一部分，并交代下一部分在哪里。

典型的顺序：

```
总览 → 推镜头到 A → 变形成 A 的细节图 → 在细节图里逐个推镜头 → 回到总览
     → 推镜头到 B → 变形成 B 的细节图 → …… → 回到总览
```

### 1.6 编排：中间帧也要能看

转场不是只有起点和终点，中间每一帧读者都会看到。播放器已经把一次变形分成几个阶段：只在前一张的东西先淡出，共享的概念再移动和变形，只在后一张的东西最后淡入，分组框的标题最后到位。作者要负责的是：

- **不要让文字在半路相撞**。两个概念的移动路径交叉，或者新出现的文字正好落在别人的飞行路径上，中间帧就会字压字。先调布局，让共享概念在两张图里的相对位置尽量一致。实在调不开，再用 deck.json 的 `timing` 给某个概念单独的移动时间段。
- **不要一次动太多**。如果一次转场里大半个画面都在动，而且路径交叉，就拆成两步：先在原图上推镜头，再变形。

### 1.7 节奏与可读性

- **停留时长随要读的内容变化**。录视频时，每页默认停留 2 秒，再加上每行要读的字 0.2 秒，限制在 2 到 6 秒之间。「要读的字」指这一页新出现的，加上镜头刚推到、上一页还没被聚焦的。某一页需要更久，就在 deck.json 里给它写 `hold`。
- **镜头下要读的字，在屏幕上不能太小**。在 1920×1080 的画面上，每一页停下来时要读的字不小于约 12px（检查脚本会报 `SMALL`）。总览图全屏显示时字往往偏小，所以不要在总览上讲细节，推镜头过去讲。
- **画布不要超出 1920×1080 太多**。整张图显示时的缩放比例是 min(1920 / 画布宽, 1080 / 画布高)。宽不超过 1920、高不超过 1080 的画布，字至少按原大小显示，扁长的流程图（比如 1920×520）也没问题；哪一边超出，就按那一边缩小：2400×1000 的画布缩到 0.8 倍，15px 的字只剩 12px。
- 转场时长的默认值（镜头移动约 1 秒，跨图变形约 1.4 秒）已经调过，一般不用改。

### 1.8 视觉语言统一

动态 deck 用的就是同一套手绘图：同样的调色板、字体、形状语义，同样没有 emoji。动效只有四种：镜头推拉、概念变形、淡入淡出、焦点外压暗。不加翻页、旋转、闪白、弹跳这类特效。

## 2. 工作流

### Step 1：故事板

先写逐页表，再画图。每一行是一页（`examples/water-supply/deck.json` 就是下面这张表）：

| 页 | 图 | 镜头 | 这一页讲的一句话 |
|---|---|---|---|
| 1 | 总览 | 全图 | 水从水库到水龙头经过四段 |
| 2 | 总览 | 水厂 | 水厂负责把原水变成自来水 |
| 3 | 水厂 | 全图 | 水厂里有四道工序，最后存进清水池 |
| 4 | 水厂 | 过滤、消毒 | 过滤去掉颗粒，消毒杀灭细菌 |
| 5 | 总览 | 全图 | 处理好的水进入管网送到各家 |

从表里数出需要几张图。每张细节图都应该能在表里找到「先推镜头到它」的那一页。

### Step 2：概念表（带 id）

在 `diagram-binding.md`（从 `templates/diagram-binding.md` 复制）里，除了颜色绑定，还要填「概念 id」一节：每个跨图出现的概念一行，写上 id、它属于谁（parent）、出现在哪几张图。画图时照着这张表写 id，不要现场起名。填好的样子见 `examples/water-supply/diagram-binding.md`。

### Step 3：画每一张图

按 SKILL.md 的 Step 1 到 Step 5 画，每张图都要渲染成 PNG 自检通过。区别有两点：

- 跨图出现的概念，在 helper 的最后一个参数里写上 `{ id }`（用法见第 4 节）。
- 画布尺寸按第 1.7 节选。模板结尾的 `main();` 和 `window.__renderDone = true;` 两行保持原样，构建脚本靠它们找到插入点。

### Step 4：写 deck.json

放在各图 HTML 的同一个目录里（格式见第 3 节）。

### Step 5：构建

```bash
python3 <skill-dir>/deck/build.py <workdir>/deck.json        # 输出 <workdir>/deck.html
```

构建时会打印每张图找到的 id 数，以及有多少条箭头连上了两端的概念。以下情况会给出警告：同一个 id 在一张图里画了多次；id 落在了不能变形的笔画上。`focus` 里写了图上没有的 id 时，构建直接报错退出，并列出这张图上有哪些 id。

构建、检查、录制都需要 Python 3.8+ 和 Playwright：`pip install playwright && playwright install chromium`。Pillow 可选，没有时条带图会存成单帧图片 `strip_<i>_<j>_p<进度>.png`。录视频还需要 ffmpeg。

### Step 6：检查

```bash
python3 <skill-dir>/deck/check.py <workdir>/deck.html --strips <workdir>/strips
```

逐页打印行数、要读的行数和最小字号。逐个跨图转场打印：哪些概念配上了（列出 id）、配上了几行文字、几根箭头。末尾汇总问题，怎么修见第 5 节。出现 `LOST` 或 `ERROR` 时退出码为 1。`--min-px` 可以改可读字号的下限（默认 12）。

手绘笔触每次构建都会重新随机，所以两次运行之间，字号、重叠面积这类数字会有零点几的差别，这是正常的。

### Step 7：看条带图

`--strips` 会为每个跨图转场保存一张条带图 `strip_<i>_<j>.png`：7 个画面排成两列，从左到右、从上到下依次是转场进行到 0、20%、35%、50%、65%、80%、100% 时的样子，最后一格空白。数字只能帮你找出嫌疑，最后要靠看图判断。逐张看：

- 每个共享概念能不能用眼睛一路追下来，有没有在半路消失再冒出来。
- 箭头是不是一直连着两端，是不是只有一根、粗细正常。
- 有没有字压字，有没有方框已经到位、字还在别处飞。
- 拆出来的子概念，是不是从父概念里长出来的，而不是从画面角落飞进来。

方框撑开成分组框（或反过来）时，中途四条边会一粗一细，这是横竖缩放比例不同造成的，属于正常现象。

### Step 8：交付

- **deck.html**：单个文件，不需要网络和服务器，用浏览器打开即可。
  - 下一页：`→`、`↓`、`PageDown`、空格、回车，或点击画面（左侧五分之一以外的地方）。
  - 上一页：`←`、`↑`、`PageUp`、`Backspace`，或点击画面左侧五分之一。
  - `Home` / `End` 跳到首页或末页，`F` 切换全屏；URL 末尾加 `#5` 直接打开第 5 页。
- **视频**（用户需要时）：

  ```bash
  python3 <skill-dir>/deck/record.py <workdir>/deck.html              # → deck.mp4，画面尺寸（默认 1920×1080），60fps
  python3 <skill-dir>/deck/record.py <workdir>/deck.html --scale 2    # 两倍尺寸，默认即 3840×2160
  ```

  录制是逐帧截图，所以转场在视频里和在浏览器里完全一样，与机器快慢无关。每页停留多久见第 1.7 节；视频开头从纸色淡入 0.8 秒，结尾淡出 1.5 秒，最后一页为此多停 1.5 秒。

把 `deck.html`（或 mp4）连同各图的 PNG 一起交付。HTML 源文件和 `deck.json` 留在原处，方便以后修改。

## 3. deck.json

```json
{
  "title": "城市供水 · 从水库到水龙头",
  "diagrams": {
    "overview": "01_overview.html",
    "plant": "02_plant.html"
  },
  "slides": [
    { "diagram": "overview", "note": "水从水库到水龙头经过四段" },
    { "diagram": "overview", "focus": ["plant"], "note": "水厂负责把原水变成自来水" },
    { "diagram": "plant", "note": "水厂里有四道工序，最后存进清水池" },
    { "diagram": "plant", "focus": ["filtration", "disinfection"], "note": "过滤去掉颗粒，消毒杀灭细菌" },
    { "diagram": "overview", "note": "处理好的水进入管网送到各家" }
  ]
}
```

| 字段 | 含义 |
|---|---|
| `title` | 浏览器标签页上的标题 |
| `diagrams` | 图的简称 → HTML 文件（相对 deck.json 的路径） |
| `slides[].diagram` | 这一页用哪张图 |
| `slides[].focus` | 镜头。不写就是整张图；写 id 列表时取这些概念的外接框；也可以直接写画布坐标 `[x, y, w, h]` |
| `slides[].note` | 这一页讲的一句话。不显示在画面上，是给作者看的提纲，检查和录制时会打印出来 |
| `slides[].hold` | 录视频时这一页停留的秒数，不写则按第 1.7 节计算 |
| `durations` | 可选，`{ "camera": 1050, "morph": 1350 }`，单位毫秒 |
| `timing` | 可选，`{ "<id>": [开始, 结束] }`，0 到 1 之间。让这个概念在每次变形中只在这段时间里移动。只在调布局解决不了相撞时使用 |
| `dim` | 可选，焦点以外部分的不透明度，默认 0.13 |
| `maxZoom` | 可选，镜头相对全图的最大放大倍数，默认 1.75。字太小时，先把细节画成单独的图，而不是调大这个值 |
| `stage` | 可选，画面尺寸，默认 `[1920, 1080]`。检查和录制都按这个尺寸进行 |

## 4. 身份 API

能成为概念、参与变形的是：方框类（`node`、`box`、`channel`、`hexagon`）、多笔画的整体形状（`taskCard`、`bubble`、`timeline`）、分组框 `frame`、带 id 的文字（`lbl`、`plain`、`title`、`subtitle`），以及箭头 `arrow`。图例 `legend` 不参与。

身份写在 helper 的最后一个参数里，静态渲染完全忽略它，只有构建 deck 时才读取：

| 字段 | 写在哪里 | 含义 |
|---|---|---|
| `id` | 上面列出的任何 helper | 概念的 id，跨图共用 |
| `parent` | 同上 | 这个概念属于哪个概念。画在父概念的方框或分组框里时可以省略 |
| `from` / `to` | `arrow` | 箭头连接的两个概念。省略时按端点推断：取端点附近最小的、带 id 的方框或分组框 |

写法（第一行摘自 `examples/water-supply/`）：

```js
channel(900, 295, 260, 70, C.im, { id: 'pipe-network' });
node(x, y, w, h, C.agent, '水厂', '净化 · 消毒', { id: 'plant', box: { strokeWidth: 3 } });  // 和 node 自己的选项写在一起
node(x, y, w, h, C.user, '用户', { id: 'users' });                    // 没有副标题时直接跟身份
box(x, y, w, h, C.memory, { id: 'tank', strokeWidth: 3 });            // box 的最后一个参数本来就是选项对象
frame(x, y, w, h, C.agent, '水厂', { id: 'plant' });                  // 可选参数（标题宽度）可以省略
bubble(x, y, w, h, C.im, { id: 'notice' });                           // 同上（气泡尾巴方向）
taskCard(x, y, w, h, C.subagent, { id: 'work-order' });
timeline(x1, y, x2, marks, { id: 'season' });
node(x, y, w, h, C.memory, '污泥池', '', { id: 'sludge-tank', parent: 'plant' });  // 画在水厂框外面，所以显式写 parent
arrow(x1, y1, x2, y2, { from: 'plant', to: 'pipe-network' });         // 端点没贴着方框时才需要写
lbl({ text: '水厂', x, y, w, color: C.agent.stroke, id: 'plant' });    // lbl / plain 把 id 写在自己的选项对象里
title('城市供水', 90, 80, { id: 'deck-title' });
```

几条约定：

- 一个概念在一张图里只画一次，所以同一个 id 在一张图里只出现一次。同一个概念画了多个副本时，构建会警告，多出来的副本会从唯一的那个伙伴里拆出来、或合并进去。
- 父子关系只写一层：工序属于水厂，水厂属于供水系统，不要让工序直接指向供水系统。
- 方框里的那行名字，不需要另外写 id，它跟着方框走。

## 5. 检查报告怎么读

| 报告 | 意思 | 怎么修 |
|---|---|---|
| `LOST` | 两张图上都有这个 id，但它没有变形过去，而是淡出再淡入 | 确认两张图里写的是同一个 id，且写在了第 4 节列出的 helper 上 |
| `REAPPEARS` | 同样的文字在一侧淡出、在另一侧淡入，读者会看到它消失再出现 | 两边写上同一个 id |
| `COLLIDES` | 两行不同的字在转场中途重叠超过半个字高。报告最严重的一刻，以及在采样帧里持续了几帧 | 先调布局；调不开再用 `timing` 错开其中一个概念的移动时间 |
| `SMALL` | 某页停下来时，有文字在画面上小于 `--min-px`（默认 12px） | 推镜头讲这一部分，或者把它画成单独的细节图 |
| `ERROR` | 页面执行出错 | 看报错，通常是某张图的 `main()` 本身就有错，先单独渲染那张图 |

检查发现不了所有问题，比如变形路径好不好看、页面节奏对不对，这些只能看条带图和实际放映来判断。
