# 垂直搜索引擎 概念 → 颜色字典

适用：垂直搜索 / 站内搜索 / 爬虫 / 索引构建 / 检索排序等主题的系列配图。按 `templates/domain-dictionary.md` 的格式填写；配套的完整示例（绑定表 + 3 张图）见 `examples/vertical-search/`。

## 主表

| 颜色 slot | 本领域类别 | 常见别名 (alias) | 默认 shape |
|---|---|---|---|
| **`C.user`** 钢蓝 | 用户 / 入口 | 用户 · 搜索框 · App · API 调用方 | Box |
| **`C.external`** 墨灰 | 数据源 | 目标网站 · 合作方 Feed · 开放 API · 第三方数据 | Box (实线 = 真实抓取 / 调用的来源) |
| **`C.subagent`** 焦糖 | 离线建库 | 爬虫 · 解析抽取 · 去重清洗 · 建索引 · 增量更新任务 | Box; 多组件时外加同色虚线 `frame()` |
| **`C.agent`** 砖橙 | 在线检索 (本领域主角) | Query 理解 · 纠错 · 意图识别 · 召回 · 粗排 / 精排 · 结果组装 | Box; 多组件时外加同色虚线 `frame()` |
| **`C.memory`** 栗棕 | 存储 | 倒排索引 · 正排库 · 向量库 · 缓存 · 原始网页库 | Box |
| **`C.llm`** 靛紫 | 模型 | Embedding 模型 · 排序模型 · Query 改写模型 | Box |
| **`C.im`** 墨青 | 队列 | URL 抓取队列 · 增量更新消息 · 日志流 | Channel (扁长条) |
| **`C.error`** 砖红 | 异常 | 降级 · 熔断 · 超时 · 抓取失败 · 反爬封禁 | Hexagon; 异常路径用红色虚线箭头 |

`C.tools` 苔绿本领域不用；遇到确实是"可调用能力"的组件（如分词服务被多个子系统共享调用）再按决策树追加。

## 形状二级区分

| slot | 子概念 | shape | 说明 |
|---|---|---|---|
| `C.subagent` / `C.agent` | 子系统内多个步骤 | 多个 Box + 同色虚线 `frame()` 圈起 | 步骤之间靠名称和序号区分，不拆颜色 |
| `C.memory` | 总览图里的全部存储 | 合并为一个 "索引存储" Box | 放大图里再拆成倒排 / 正排 / 向量库 |
| `C.im` | 队列 | Channel | 和 Box 区分开："流过的东西" vs "常驻的东西" |

## 决策树 · 拿到一个名词怎么定色

```
是不是发起搜索的人或调用方?
  └ Yes → C.user
是不是系统外部、被抓取或被调用的数据来源?
  └ Yes → C.external
是不是排队等待处理的消息 / URL / 事件?
  └ Yes → C.im (Channel)
是不是响应搜索请求的在线链路步骤?
  └ Yes → C.agent
是不是把原始数据加工成索引的离线步骤?
  └ Yes → C.subagent
是不是训练出来、负责打分或转向量的模型?
  └ Yes → C.llm
是不是被读写的数据本身 (索引 / 库 / 缓存)?
  └ Yes → C.memory
是不是失败 / 降级 / 熔断?
  └ Yes → C.error
实在归不到? → 优先合并到最近的 slot, 不要开新色; 或者改用形状区分。
```

## 互斥规则

1. **向量库 ≠ Embedding 模型**——向量库存数据，是 `C.memory`；生成向量的模型才是 `C.llm`。
2. **建索引 ≠ 索引**——建索引是离线加工动作，`C.subagent`；索引本身是存储，`C.memory`。
3. **缓存 → `C.memory`**，即使它部署在在线链路里。颜色表示"它是什么"，不表示"它在哪条链路"。
4. **主角颜色固定给在线检索**。画离线建库放大图时，离线流水线是该图主体，但仍用 `C.subagent`，靠尺寸和加粗突出，不借用 `C.agent`。否则同一概念会在不同图里换色。
5. **召回 / 排序算法步骤 ≠ 模型**——"多路召回""精排"是在线链路步骤 (`C.agent`)；它们调用的排序模型单独画成 `C.llm` Box。
