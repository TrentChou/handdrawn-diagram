# Palette · 9 固定角色色（低饱和暖色 / 米白底版）

文章里所有图共用这一套调色板。**同一角色在每张图里永远用同一种颜色**。

> **可视化样张**：[`../examples/concept_palette_cheatsheet.png`](../examples/concept_palette_cheatsheet.png) — 一张图看全 9 色 slot + 概念 alias + shape 速查 + 通用色 + 字体 demo。

## 设计原则

整套色卡走"**低饱和暖色 + 米白底**"路线，灵感源自纸面阅读 / Solarized Light 暖色主题：

1. **底色 `#fdfdfa`**（暖米白，253/253/250）—— 不用纯白，不刺眼，有"纸面"质感
2. **每个角色的 fill 是同色相极淡浅色**，和底色融为一体；solid 化后是"轻轻染色的便利贴"
3. **每个角色的 stroke 是同色相深沉中性化深色**，**同时也作为节点内文字色**；对自家 fill 的对比度全部 ≥ 4.5:1（WCAG AA），多数在 5-7:1 之间
4. **整体微偏暖**（蓝→钢蓝、青→墨青、绿→苔绿等），避免和暖底色相冲突
5. **文字色 = 节点 stroke 色**——同色相的深浅版本，色相一致最显专业；不要节点是橙底但文字突然换中性灰

## 角色色

slot 名沿用 Agent 领域的叫法（`C.user` / `C.agent` …），但每个 slot 背后是一个**抽象语义**。画非 Agent 领域时按"抽象语义"列对应，不按 slot 名字面意思。

| Slot | Stroke (= 节点内文字色) | Fill (背景) | WCAG 对比度 | 抽象语义（跨领域） | Agent 领域的用法 |
|---|---|---|---|---|---|
| **`C.user`** | `#1f5582` 钢蓝 | `#e3ebf2` 雾蓝 | 6.5:1 | 人 / 发起者 / 系统入口 | 用户、人类输入端、人类审批 |
| **`C.im`** | `#106668` 墨青 | `#dde8e7` 雾青 | 5.4:1 | 通道 / 传输 / 队列 / 消息 | 微信 / Telegram / 任何消息通道、Bus、队列 |
| **`C.agent`** | `#a04a1f` 砖橙 | `#f3e2cf` 米橙 | 4.7:1 | 本图主角 / 核心子系统 / 控制面 | 主 Agent / Orchestrator / 编排核心 |
| **`C.subagent`** | `#7d4f0a` 焦糖 | `#f4eacd` 麦黄 | 5.8:1 | 执行者 / 次要子系统 / 处理流水线 | 子 Agent / Worker / Verifier |
| **`C.llm`** | `#4a3f8c` 靛紫 | `#e6e2ef` 雾紫 | 6.9:1 | 模型 / 算法 / 推理 | LLM、推理模型、Reasoner |
| **`C.tools`** | `#2f6b3c` 苔绿 | `#dfead9` 雾绿 | 5.1:1 | 能力 / 工具 / 隔离环境 | 工具调用、MCP server、Sandbox |
| **`C.memory`** | `#6e554a` 栗棕 | `#ede2d5` 牛皮 | 5.4:1 | 存储 / 持久化 / 数据 | 记忆、KV / DB / 向量库 |
| **`C.external`** | `#4f5359` 墨灰 | `#e9e7e3` 暖灰 | 6.3:1 | 外部依赖 / 背景参照 | 第三方 API、外部服务、行业对照 |
| **`C.error`** | `#a52928` 砖红 | `#f0d8d2` 浅赭 | 5.2:1 | 异常 / 失败 / 降级 — **克制使用** | 异常路径、兜底、失败分支 |

> 对比度按 WCAG 2.1 相对亮度公式计算（stroke 对 fill）。AA 正文门槛 ≥ 4.5:1，AAA 正文门槛 ≥ 7:1。
> 整套 9 色全部达到 AA；没有一组达到正文 AAA（最高 llm 6.9:1）。节点主标是 ≥ 22px 粗体，属于 WCAG 的"大字"，大字 AAA 门槛是 4.5:1，全部满足。

## 用色纪律

1. **颜色数量按需求定**：需求里出现几类概念就用几种颜色，最多 9 种。这套色饱和度低、明度接近，9 色同屏也不打架（正常视力下任意两色描边 ΔE2000 ≥ 13，明显可分）。超过 5 种时加一个简洁的颜色图例（`legend()`，只列本图用到的颜色），否则读者记不住每种颜色代表什么。
   - **颜色不能是唯一线索**：红绿色盲（男性约 8%）下 Agent / Sub-Agent、User / LLM、IM / External 三对 ΔE 只有 3-6，几乎分不清。所以每个节点都必须有文字标签，必要时再用形状区分。
   - 图太密读不动时，拆成总览图 + 子系统放大图。拆图是为了可读性，不是为了凑颜色数。
2. **箭头一律暖墨色 `#3a3530`**。线不上色，节点用色区分；线上色 = 整张图崩。
3. **红色只用于异常路径**。一旦正常流程也用红，读者就分不清主次。
4. **不要为单图新增角色色**。需要表达新概念时，优先换形状（卡片 / 气泡 / 六边形 / 时间线），不开新色。
5. **主角加粗加大**：主 Agent 的盒子永远比其他大 1.3-1.5 倍，描边加粗到 3px；这样不靠"颜色更亮"也能突出。
6. **节点内文字色 = 节点 stroke 色**。同色相深浅对比，色相统一最显克制。不要拿黑色 / 中性灰当节点内文字色，也不要拿对比色当文字（如蓝节点橙字）。
7. **对比度 ≥ 4.5:1**。新增角色或调色时，**必须**先验算 stroke 对 fill 的 WCAG 对比度，未达 4.5 就别用。

## 颜色来源说明

这套色不是常见白板工具默认的 [Open Color](https://yeun.github.io/open-color/) 高饱和色（太鲜艳），是为"印刷字 + 手绘形状 + 米白底"组合**专门调过**的低饱和暖色版。在其他绘图工具里使用时，按上表填 hex 值即可。

设计参考：
- **Solarized Light** 的暖底色和低饱和理念
- **iA Writer** / **Bear** 这类长文阅读软件的纸面感
- **羊皮纸 / 旧报纸**的暖白基调（253/253/250 接近 ivory）
- **WCAG 2.1** 对比度规范（AA 4.5:1 起）

## 概念 → 颜色映射

上表 9 色是**槽位**，每个槽位下可能装多个具体概念。一个领域的概念怎么归到 9 个槽位，写在 `references/domains/` 下的领域字典里：

| 领域字典 | 适用 |
|---|---|
| [`domains/agent-team.md`](./domains/agent-team.md) | Agent Team / Multi-Agent / Memory / coding agent / 文档 / 研究流水线 |
| [`domains/vertical-search.md`](./domains/vertical-search.md) | 搜索引擎 / 爬虫 / 索引 / 检索排序 |

每份字典包含：概念 alias 主表、shape 二级区分、「拿到名词怎么定色」的决策树、互斥规则、系列配图色覆盖建议。

没有现成字典的领域：按"抽象语义"列对应，用 [`../templates/domain-dictionary.md`](../templates/domain-dictionary.md) 写一份新字典（只服务一组图时，直接填 `templates/diagram-binding.md` 即可）。

简言之：**同一个概念在所有图里永远是同一颜色 + 同一形状基线**。靠字典 + 绑定表锁住一致性，不靠记忆。
